## Что это

Переписанный под Windows аналог Applio: берёт звук с микрофона, прогоняет через RVC-модель и отдаёт в виртуальный микрофон, который видят Discord, OBS, игры и любые другие программы.

Ничего настраивать вручную не нужно — Python, PyTorch, бэкенд и базовые модели программа скачивает и устанавливает сама при первом запуске.

## Что нового в 1.2

### Второй источник моделей: voice-models.com

В парсере появился выпадающий список **«Сервис»** — теперь можно переключаться между HuggingFace и **voice-models.com** без перезапуска.

**voice-models.com** — каталог с поиском прямо по имени голоса. Особенности реализации:

- Пагинация работает через тот же POST-запрос (`fetch_data.php`), что делает сайт при клике по номеру страницы — поэтому все страницы доступны, а не только первая
- Скачивание поддерживает HuggingFace, Google Drive, weights.gg, pixeldrain, Discord CDN, GitHub, Dropbox и ряд других хостингов
- Google Drive-ссылки автоматически нормализуются к прямому эндпоинту с подтверждением (`drive.usercontent.google.com`) — браузер для этого не нужен
- Если прямая ссылка в таблице отсутствует, воркер лениво заходит на страницу модели и берёт её оттуда
- Файлообменники без прямого API (MEGA, Mediafire, Gofile и др.) определяются автоматически: вместо тихого скачивания HTML-заглушки выводится диалог с предложением открыть ссылку в браузере
- Тип скачиваемого файла определяется по сигнатуре (`PK` для ZIP), а не по расширению в ссылке — Google Drive часто отдаёт ZIP без расширения в имени

### Поддержка AMD и Intel Arc (DirectML)

Видеокарты AMD Radeon и Intel Arc теперь задействуются через **DirectML** — GPU-вычисления поверх DirectX 12. Никаких дополнительных SDK, никакого ROCm — работает на Windows 10 (1903+) и Windows 11 из коробки.

- При первом запуске программа автоматически обнаруживает AMD/Arc карту и предлагает включить DirectML одним нажатием
- Переключиться с CUDA на DirectML и обратно можно в **Настройках** без потери окружения
- Кнопка **«Установить DirectML»** доустанавливает нужные пакеты (~2 ГБ) в уже готовое окружение
- Кнопка **«Вернуть CUDA»** — полноценный откат к NVIDIA-сборке torch, включая исправление numpy

> AMD Radeon RX 5000 и новее, Intel Arc A-серия и B-серия поддерживаются официально. RX 9070 и другие RDNA 4 наблюдаются проблемы из за драйверов.

### Автовосстановление окружения

Повреждённое окружение (конфликты версий, незавершённая установка, артефакты после экспериментов с DirectML) больше не требует ручного вмешательства:

- **Проверка torch при старте** — если в site-packages обнаружена не та версия пары torch/torchaudio, штамп установки сбрасывается и окружение пересобирается при следующем запуске
- **Авторемонт torch** — если самопроверка выявила битые нативные библиотеки (WinError 127, «не найдена указанная процедура»), установщик физически удаляет папки torch и переустанавливает нужную сборку
- **Авторемонт numpy** — после DirectML в окружении мог остаться numpy 2.x, который ломает faiss и numba; откатывается в совместимую версию 1.x автоматически
- **pip-constraints** — при каждой установке пакетов записывается файл ограничений, который не даёт случайной зависимости поднять torch или numpy до несовместимой версии
- **Автообновление воркера** — `vc_worker.py` перезаписывается из программы при каждом запуске; исправления доезжают сразу, без переустановки окружения

### Аварийный переход на CPU при ошибках GPU

DirectML не поддерживает все операторы PyTorch. Если видеокарта не вытянула пайплайн и одна и та же ошибка повторилась 5 раз подряд, воркер **автоматически пересобирает движок на CPU** — голос продолжает идти, задержка вырастает, но разрыва нет. В интерфейсе появляется предупреждение с текстом ошибки и местом в коде, где она возникла.

### Улучшенная диагностика ошибок

- Ошибки из C++-ядра PyTorch на русской Windows раньше приходили как `UnicodeDecodeError` вместо читаемого текста — теперь раскодируются через cp1251/cp1252 с fallback на latin-1
- К каждой ошибке прикладывается цепочка кадров стека (`файл:строка → функция`) — сразу видно, где именно упало
- При подключении воркера в лог пишется его версия — видно, какая именно копия скрипта запущена

### Индикатор прогрева модели

Пока модель загружается после нажатия «Старт», в интерфейсе показывается баннер с прогресс-баром. На выход в этот момент идёт тишина — об этом теперь явно сообщается.

### Настройки ускорения и качества звука

> Если обновляетесь с 1.0–1.1, все опции появятся в **Настройках** автоматически после первого запуска.

**GPU и точность вычислений:**
- **Режим точности** — fp32 / fp16 / bf16 / авто. Fp16 и bf16 задействуют Tensor Cores на RTX 20xx и новее
- **TF32** — ускоряет fp32 на Ampere (RTX 30xx+) почти без потерь точности, включён по умолчанию
- **torch.compile** — срезает накладные расходы через CUDA Graphs; первый старт после включения занимает 30–60 с
- **Уменьшить синки GPU→CPU** — один синк за блок вместо двух-трёх

**Качество звука:**
- **Кольцевой буфер** — настоящее кольцо вместо сдвига буфера с клонированием; снижает нагрузку на CPU
- **Интерполированная огибающая** — линейный рамп громкости вместо ступенчатого скачка; устраняет АМ-артефакт ~7.8 Гц
- **Soft-gate** — мягкое открытие/закрытие вместо резкой обрезки тишины; убирает щелчки на входе и выходе из речи. Настраиваются время удержания, атаки и отпускания (мс)

## Возможности

- **Один файл.** Самодостаточный `RvcVoiceChanger.exe` — .NET и Python ставить не надо.
- **Автоустановка при первом запуске.** Portable Python 3.11.9, PyTorch (CUDA при NVIDIA с драйвером ≥ 525, DirectML при AMD/Arc по запросу, иначе CPU), RVC-бэкенд и модели rmvpe/contentvec. Повторно ничего не качается — ведётся штамп установки.
- **Реальное время.** WASAPI-захват, вывод в виртуальный микрофон и самопрослушку, индикаторы уровня и задержки.
- **Два источника моделей.** HuggingFace (по авторам + пагинация) и voice-models.com (поиск по голосу + пагинация). Переключается прямо в интерфейсе парсера.
- **Своя библиотека моделей.** Добавление `.pth` + `.index` вручную или из ZIP, переименование, удаление.
- **Прокси.** HTTP и SOCKS5 с логином/паролем (шифруется через DPAPI), отдельные галочки для pip и HuggingFace, зеркало PyPI, кнопка «Проверить соединение». Прокси пробрасывается в дочерний Python. Логин и пароль маскируются во всех логах.
- **Самопроверка.** `vc_worker.py --selftest` проверяет torch, CUDA/DirectML, librosa, faiss, transformers, pedalboard, бэкенд и наличие весов.
- **Живые логи.** Фильтр по уровню и поиск, дублирование в `logs/app-ГГГГ-ММ-ДД.log` (хранятся 14 дней).
- **Portable-режим.** Пустой файл `portable.txt` рядом с `.exe` — все данные лежат в папке `RvcData` рядом с программой.
- **Тёмная и светлая темы.**

## Быстрый старт

1. Скачайте `RvcVoiceChanger.exe` из [Releases](../../releases).
2. Запустите и дождитесь окончания автоустановки.
3. Нажмите **«Установить виртуальный микрофон»** — будет скачан и установлен бесплатный VB-CABLE (один UAC-запрос).
4. На вкладке **Модели** или **Парсер моделей** добавьте голосовую модель.
5. На вкладке **Изменение голоса** выберите модель и микрофон, задайте высоту тона и нажмите **Старт**.
6. В Discord / OBS / игре выберите микрофон **CABLE Output**.

> Кнопка **«Проверка»** позволяет услышать себя до того, как вас услышат другие.

### Подключить AMD или Intel Arc

1. После установки откройте **Настройки → Вычисления → Устройство** и выберите **DirectML**.
2. Нажмите **«Установить DirectML»** — загружается совместимая сборка torch (~2 ГБ).
3. Перезапустите программу — обработка пойдёт на видеокарте.

Вернуться к CUDA: кнопка **«Вернуть CUDA»** в том же разделе.

## Как работает парсер моделей

### HuggingFace

Страница `huggingface.co/models?other=rvc` рисуется на JavaScript, поэтому используется официальный публичный API.

1. `GET /api/models?filter=rvc&sort=downloads&limit=N&skip=M` — список авторов с пагинацией.
2. `GET /api/models/{repo}/tree/main?recursive=true` — файлы с размерами (кэш 15 мин против rate-limit).
3. Валидный репозиторий — тот, где есть `.zip` либо пара `.pth` + `.index`. Если есть оба варианта — предлагается ZIP.
4. Служебные веса отсеиваются (`hubert*`, `rmvpe*`, `fcpe*`, `contentvec*`, `pretrained*` и т.п.) по границам слов.
5. Скачивание через `{repo}/resolve/main/{path}` с прогрессом и докачкой по Range.

### voice-models.com

1. Первая страница и поиск — GET на главную; страницы 2+ — POST на `fetch_data.php` (так же, как делает сам сайт при клике по пагинации).
2. Адрес файла берётся из кнопки копирования в строке таблицы (`data-clipboard-text`) — там полный URL без обрезки многоточием.
3. Если ссылки в таблице нет — воркер лениво заходит на страницу модели (`/model/<id>`) и ищет блок «Download Link».
4. Google Drive-ссылки нормализуются к прямому эндпоинту с подтверждением скачивания.
5. Хостинги без прямого API (MEGA, Mediafire, Gofile и др.) помечаются как «только браузер» — выводится диалог с предложением открыть ссылку вручную.
6. ZIP определяется по сигнатуре `PK`, а не по расширению.

## Виртуальный микрофон

Windows не позволяет создать виртуальный микрофон из обычного приложения — нужен драйвер режима ядра. Поэтому используется бесплатный **VB-CABLE**:

- программа пишет голос в **CABLE Input**;
- в сторонних приложениях выбирается микрофон **CABLE Output**;
- URL установщика можно переопределить настройкой `VbCableUrl`, SHA-256 архива пишется в лог.

## Где хранятся данные

```
%LOCALAPPDATA%\RvcVoiceChanger\
  runtime\
    python\   portable Python 3.11.9 + пакеты
    backend\  RVC-бэкенд + rmvpe.pt / contentvec (+ fcpe.pt, если скачался)
  models\     ваши голосовые модели
  downloads\  скачанные архивы
  logs\       журналы
  settings.json, models.json
```

Путь бэкенда прописывается в `python311._pth` относительным путём, поэтому папку рантайма можно свободно переносить.

| Ключ | Зачем |
|---|---|
| `PythonZipUrl` | зеркало python.org |

## Архитектура

```
WPF UI (C#) ── WASAPI захват ── блоки float32 48кГц
                                  │  TCP 127.0.0.1 (бинарные кадры)
                          vc_worker.py ── rvc.realtime.core.VoiceChanger
                                  │
            WASAPI вывод ── CABLE Input + (опционально) наушники
```

Почему Python внутри, а не чистый C#: веса RVC — это PyTorch-чекпоинты, а индексы — faiss. Порт на ONNX ломает совместимость с чужими `.pth` с HuggingFace, а именно их и качает парсер. Пользователь Python не видит — он спрятан в папке данных.

## Известные особенности

- Первый запуск требует интернета и качает 3–6 ГБ (CUDA) или ~2 ГБ (DirectML/CPU).
- DirectML медленнее нативной CUDA: ожидаемо 50–70% скорости. При 5 последовательных ошибках GPU воркер автоматически переходит на CPU.
- Без GPU ставится CPU-версия PyTorch: работает, но задержка выше — ставьте размер чанка от 192.
- `torch.compile` требует «прогрева» 30–60 с при первом включении.
- Антивирус может ругаться на неподписанный single-file exe.
- `fcpe` опционален: если не скачался, выводится предупреждение, остальное работает.
